# 日常 Chrome

独立工具插件，维护页面、Chrome 检测、原生授权握手、状态、重连及 CDP 会话隔离。使用 SDK 2.2.1 公共页面/主题协议，不导入宿主私有模块，不读取宿主配置或凭据。

## 使用与边界

- 安装在运行于本机的工作台，不在远程服务器代开用户 Chrome；此版本不声明个人 Agent 部署协议。
- 当前仅支持 macOS 日常 Google Chrome。只读检查 Chrome 的公开 `DevToolsActivePort`，不读取 Cookie、密码或登录配置内容。
- 安装时须确认本机代码信任及声明权限。此插件是可信本机代码，不是操作系统安全沙箱。
- 页面先显示真实检测状态，连接前确认用途，再由用户在 Chrome 中允许连接。取消不发出连接请求；打开设置不自动开启远程调试。
- 缺失提示末尾提供[官方安装说明](https://agent-browser.dev/installation)，点击使用系统默认浏览器打开；插件不会代为安装或执行网页命令。
- `agent-browser` 可选。缺少它不阻止连接 Chrome，也不阻断普通 AI 会话、代码或接口任务。
- 浏览器连接、目标网站登录、实际业务验证分别记录，不能把“已连接”当成已登录或业务通过。
- 每个消费者拥有独立的 CDP browser session，不共享请求路由；拒绝来自网页 Origin 的 WebSocket 连接，不转发 Browser.close。
- 页面销毁清理轮询和主题订阅。隐藏菜单、关闭页面不等于断开；停用、移除或退出宿主关闭插件自有连接，不退出 Chrome 或停止外部服务。
- 插件自己的连接偏好保存在插件隔离数据目录。不会自动读取或迁移原宿主私有连接偏好。重启宿主后需重新打开插件并连接。

## AI 会话接入

`browser.connection` v1 声明 `browser/status` 与 `browser/session`。状态不包含调试地址；`browser/session` 仅允许宿主注入的可信调用上下文，拒绝普通页面或插件调用获取能力地址。

宿主按声明发现已启用且授予 `application.local`、`browser.provide` 的提供者，在 AI 任务开始时取得已验证通道。`browser.provide` 可拒绝，拒绝时不向任务提供通道，连接管理仍可使用。存在多个已授权提供者时不自行选择。页面及其他插件不能获取通道地址；上下文来源由宿主 IPC 注入。撤权、停用、更新或移除会终止插件 worker 与其转发连接，既有通道失效，普通代码任务不依赖它。

安装后打开插件完成连接确认，再由用户在 Chrome 授权。不会读取旧宿主私有连接偏好，不会自动启动 Chrome 连接。宿主重启后需重新连接。

## 构建与验证

仓库根目录执行 `pnpm build && pnpm test`。产物 `dist/daily-chrome-1.0.1.dwp` 包含声明、页面、样式和后端依赖，无需安装脚本或兄弟目录。通过插件中心的检查/授权安装流程安装，不能手工修改宿主注册表。

测试使用临时目录、模拟 Chrome 和本机隔离端口，不连接真实 Chrome、不读取真实账号、不操作业务页面。
